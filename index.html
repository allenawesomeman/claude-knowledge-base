Architecture

四層架構，一個資料夾

Workflows

四條每天在跑的工作流

點選上方分頁切換流程，點任一節點看細節。

Tools

工具箱：每件都標清楚現在能不能用

有些是每天在用的，有些剛建好，有些還在計畫書階段。卡片上的標籤寫的是實際狀態。

Skills

Skills：同一件事做第三次，就寫成 SOP

一個 Skill 是一份 Markdown：寫明什麼時候觸發、步驟、檢核表、範本。正本放在 repo 的 .agents/skills/，Claude Code 與 Codex 透過 symlink 共用。

寫自己的論文另用 plugin academic-research-skills（/ars-plan、/ars-reviewer、/ars-citation-check）。讀別人的論文走 PLR／ILR，寫自己的論文走 ARS，兩條線不混用。

Hard-won rules

踩坑換來的規則

每一條都寫進了 CLAUDE.md 或記憶檔，背後都有一次真實的錯。

引用不信 AI 記憶

任何文獻都要經 OpenEvidence 或 PubMed 確認存在，才能寫進文件。

教訓：AI 會編出格式完美、但不存在的 PMID。

算數不心算

金額、劑量、統計一律寫 Python 腳本執行，報告附腳本路徑與輸出。

教訓：多步驟計算是語言模型最容易「看起來對」的地方。

產出必落檔

講稿、分析、討論結論都存成 主題_YYYYMMDD.md，不只留在對話裡。

教訓：對話被壓縮後，最好的那版講稿就找不回來了。

改檔先備份

cp 檔案 檔案.bak-YYYYMMDD，或確認已 commit。

教訓：知識庫裡多數檔案是唯一版本。

病人資料不上 GitHub

commit 前掃姓名、病歷號與大檔；病人資料夾不直接列目錄，用腳本只印代號。

教訓：檔名和 docx 首列本身就可能含姓名。

派工看「知不知道去哪讀」

已知路徑的檔案直接讀；只有不知道目標在哪的搜尋，才派 subagent。

教訓：每次派工冷啟動約 12k tokens，比直接讀還貴。

講稿語氣有範本

聽眾是主治醫師：客觀、實證、不輕挑。禁「首先我們看 Fig 1」這類指路句，也禁「兩者方向一致」這類空泛評語。

教訓：範例要取自本人親手改過的稿，不能拿 AI 原稿當範本。

每個專案都有「00_先看這裡」

跨 session、跨模型接手時，從入口檔與交接書讀起。

教訓：沒有交接書，新 session 會把舊坑再踩一次。
Build your own

想自己蓋一套？從這五步開始

1

先有資料夾，再有 AI

用 Obsidian 或任何資料夾整理現有筆記，git init 並設成 private repo。AI 能幫你的程度，取決於它讀得到多少你自己的東西。

2

寫一份短短的 CLAUDE.md

你的身分、輸出語言、3–5 條絕對不能錯的事。先短；被 AI 搞砸一次，就補一條。

3

接一個查證管道

醫療領域至少接 PubMed MCP，讓 AI「查到才能寫」。

4

把做第三次的事寫成 Skill

從最常做的報告格式開始（例如 journal club），範本就用你自己改過的稿。

5

養成交接習慣

每次大工程結束前，請 AI 寫一份「下次從哪裡接」的交接書，放在專案資料夾最上層。

最小可用的 CLAUDE.md

## 使用者
牙周病專科醫師。回覆用繁體中文，臨床術語保留英文。

## 鐵則
1. 引用文獻必須先用 PubMed 查到才寫
2. 產出一律存檔：主題_YYYYMMDD.md
3. 改既有檔案前先備份

## 任務路由
| 任務 | 用什麼 |
| 文獻報告 | skill journal-club |
| 查證據 | MCP pubmed |

這套環境實際用到的東西

  • Claude Code：主力，規劃、寫作、驗收
  • Codex：大量實作與抄錄（例如 125 張 slide 逐字抄錄）
  • Obsidian：閱讀與連結筆記
  • MinerU／MLX Whisper：PDF 擷取、本機語音轉錄
  • OpenEvidence／PubMed／NotebookLM：MCP 查證與提問
  • Keynote／Pages：最終簡報與講義
  • Git＋GitHub（private）：版本控制
